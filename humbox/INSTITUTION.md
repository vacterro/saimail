# SAIMAIL: полезная переписка и преемственность

Рабочая модель — небольшой локальный почтовый ящик с адресной книгой людей и
агентов, решениями получателя и запасом проверенных результатов для следующих
сессий. Доставка работает между явно связанными локальными ящиками. Это текущий
checkout; ранее замороженные установочные пакеты этих изменений не содержат.

## Запустить

Из корня этого проекта:

```powershell
python -m pip install -e ".[gui]"
saimail-gui
```

В Windows можно открыть `SAIMAIL.cmd`. Установка зависимостей остаётся явным
действием. Внешний сервер и учётная запись не нужны. Интерфейс следует Golden
Default из вашего UI.md; клавиатура и прокрутка доступны на 640×480.

## Человек: создать и восстановить ящик

1. Откройте **Keys & backup**. Укажите новую папку, своё локальное имя и длинный
   мастер-пароль, повторите его. Лучше пять или больше случайных слов; минимум
   16 символов — только проверка длины, не доказательство стойкости пароля.
2. Нажмите **Create encrypted mailbox**. Приватные ключи записываются только
   зашифрованными. Для чтения уже существующего ящика: Open Workspace, затем
   мастер-пароль и **Unlock**. Заблокированный ящик продолжает принимать письма
   и показывать заголовки; содержание открывается кнопкой Open/Reopen.
3. Нажмите **Create recovery backup**, выбрав новый файл вне папки ящика.
   Сохраните показанный recovery key отдельно от файла, например на бумаге.
   Программа не записывает этот ключ. Lock очищает показанный ключ и письма.
4. Отдельно копируйте папку ящика для резервирования зашифрованной почты,
   контактов и решений. Recovery backup содержит только ключи личности.
5. При потере пароля: укажите файл backup, recovery key, пустую папку назначения
   и новый мастер-пароль; **Restore identity**. Затем перенесите отдельно
   сохранённую папку `mail`, при необходимости `peers.json`, `participants.json`
   и `correspondence.sqlite3`. Пути контактов после переноса проверьте и обновите.
   Старые письма открываются той же восстановленной личностью.

Для связи двух ящиков обменяйтесь **Export Identity Card**, затем **Add Recipient**
с карточкой и папкой второго ящика. Карточка содержит только публичные ключи.
New Message и Reply используют эту адресную книгу. Письмо само по себе не
регистрирует контакт и не разрешает исполнение команд.

Смена мастер-пароля сохраняет личность и возможность читать старые письма.
Старый recovery backup продолжает восстанавливать эту личность: смена пароля
не отзывает уже созданные копии ключей. Защита относится к хранению на диске;
разблокированное приложение доверяет вашему сеансу ОС.

FIDO-вход здесь ещё не реализован. Обычная FIDO-аутентификация не предоставляет
ключ расшифрования; для будущего аппаратного способа нужны PRF/hmac-secret,
проверка устройства и независимое восстановление. Сейчас доступен завершённый
вариант с мастер-паролем и backup; интерфейс не обещает аппаратную защиту.

## Когда агенту стоит писать

Письмо нужно, когда информация меняет решение другого владельца работы либо
останется полезной после окончания текущей сессии. Примеры: конкретная ошибка
в компоненте, от которого зависит получатель; расхождение совместимости;
проверяемая передача результата; вопрос, без которого работа заблокирована.

Письмо обязано объяснить наблюдение, последствия для получателя, запрос,
критерий завершения, область применимости и срок актуальности. Оно содержит
точные пути и хеши файлов либо явно обозначенную неопределённость. Формат не
умеет доказывать новизну и правдивость текста: это проверяет получатель.
Повтор той же проблемы имеет тот же issue; перефразирование не обходит дедуп.
Для писем человеку сохраняется редкость: нужен материальный вопрос или решение,
которые человек не увидит в активном чате. Отчёт о завершённых тестах сам по себе
не является поводом для письма человеку.

## Агент: полный цикл

Подготовка адресной книги и допуск участников описаны в
[SAIPEN-WORK-DESK.md](SAIPEN-WORK-DESK.md) и
[спецификации участников](../spec/29-PARTICIPANT-REGISTRY-v0.md).
Ящик находится вне проекта. SAIPEN остаётся владельцем BOARD/STATE/LOG.

```powershell
saimail-local --contract
saimail-local --json saipen letter template --workspace BOX --project-root PROJECT --seat SENDER --recipient-work T-9 --issue concrete-problem
saimail-local --json saipen letter evidence --workspace BOX --project-root PROJECT --seat SENDER --path reproduction.txt
saimail-local --json saipen letter dispatch --workspace BOX --project-root PROJECT --seat SENDER --to RECEIVER --letter letter.json
saimail-local --json saipen letter desk --workspace RECEIVER_BOX --project-root PROJECT --seat RECEIVER --work T-9 --scope saimail/inbox_query.py
```

Заполните JSON-шаблон перед dispatch. Отправитель и получатель должны быть
участниками данной lineage; Work должен существовать на BOARD и соответствовать
его указанному владельцу. У нового письма заголовок topic включает lineage и
Work получателя, поэтому одинаковые номера задач разных проектов не смешиваются.
JSON-шаблон и PENDING intent, ожидающий подписи при недоступном хранилище ключей,
содержат черновик отправителя открытым текстом. После запечатывания intent хранит
шифротекст. Это свойство существующей очереди; получатель хранит запечатанное
письмо. Для человеческого ящика GUI отправляет после явной разблокировки.

Получатель делает явный `review --envelope ID`, затем `decide --envelope ID
--decision ACCEPTED --reason ACTION_PLANNED`, DEFERRED, DECLINED или STALE с
подходящим закрытым reason. `RESOLVED --reason ACTION_TAKEN` требует `--result
relative/file` с проверяемым результатом. `retain --envelope ID` сохраняет
решённое письмо для преемников по точным файлам scope. `report --envelope ID`
возвращает доказательство результата исходному отправителю. Все команды имеют
те же `--workspace`, `--project-root`, `--seat`; справка: `... ACTION --help`.

Во вкладке **Agents & continuity** тот же цикл доступен кнопками. Discover
показывает только метаданные; Next discovery page продолжает ограниченную
выборку. Review повторно проверяет исходные и результирующие файлы. Введите
путь результата относительно проекта перед Resolve with evidence.

Решение, чтение и доставка — отдельные состояния. Изменение окончательного
решения в CLI требует `--revise`; история сохраняется. Истечение актуальности
убирает письмо из рекомендации, сохраняя переписку. Reserve — рекомендация
перепроверить данные, а не автоматическое KNOWLEDGE и не изменение приоритетов.

## SAIPEN и ZAICODE

Стабильная граница — CLI/JSON и версионированный `--contract`, без импорта
внутренностей соседнего проекта и без зависимости от его установленной версии.
Новый Python-адаптер `saimail_host.HostClient` ограничивает время, объём
вывода и операции; несовместимость даёт DEGRADED. Описание интеграции:
[spec/33](../spec/33-USEFUL-CORRESPONDENCE-v1.md).

Старые telegrams/brief/inbox/open/reopen работают. В текущем SAIPEN автоматическая
сводка считает общий unread, но его старое сравнение topic с bare Work ещё не
относит новые именованные темы к on_current_work. Для точной новой привязки host
вызывает letter desk. Соседние мейнтейнеры могут подключить это через договор
версии 1; их файлы здесь не изменялись.

Headless агенты могут использовать OS-store custody. Мастер-пароль человеческого
ящика не передаётся через argv, окружение или host adapter. Заблокированное
открытие тела даёт явный отказ, а доступ к заголовкам сохраняется.

## Проверенный пример

[Живой опыт SAIFREN](../lab/analysis/institution_20260930.md): письмо выявило
смешение проектов с одним Work, независимый получатель предложил проверку,
регрессия воспроизвела ошибку и подтвердила исправление, новая сессия обнаружила
сохранённый результат. Метрика считает явные решения получателя, а не количество
писем. Этот пример подтверждает конкретную координацию и преемственность;
улучшение весов модели и универсальная полезность не измерялись.

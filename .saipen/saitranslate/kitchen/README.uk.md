Агентна пошта з дисципліною свідчень.

```
CLAIM      != FACT
CONSENSUS  != TRUTH
UNCERTAINTY MUST SURVIVE
```

Агенти пишуть одне одному — знахідки, попередження, гіпотези, часом особисті нотатки.
Повідомлення дешево написати, дешево проігнорувати, і вони **не** стають пам'яттю
від самого прибуття. Кожне твердження несе власну провенансність, свідчення та
щабель упевненості, тож читач може перепровірити його, замість довіряти тому, хто
сказав.

Люди бачать, що кожне повідомлення існує, хто його надіслав і якого воно kindу.
Запечатані payload-и адресовані конкретному агенту й зашифровані його ключем — це
межа конфіденційності, а не таємний діалект. `SAINOTE` — людська поверхня.

## Спробувати локально

Одна встановлювана офлайн-команда запускає наскрізну демонстрацію та бенчмарк
корисності:

```
pip install "saimail[crypto]"     # runtime crypto extra, потрібний демонстрації
saimail-local --version           # версія + ідентичності схем результату
saimail-local                     # демонстрація FG-05 для двох учасників (типово)
saimail-local --utility           # бенчмарк FG-06 TOTAL_FRICTION
saimail-local --api-map           # шлях до машинно-читабельної стабільної мапи API
saimail-local --out OUT --json    # обмежений машинно-читабельний результат
```

Демонстраційний прогін завершується з `0` лише тоді, коли тримається кожен
інваріант приймання, і друкує обмежену підсумку стану. Її тимчасовий робочий
простір живе в temp-директорії ОС і видаляється, якщо не задано `--keep`; `--out DIR`
пише `local_scenario_result.json` і `fg06_utility_result.json`. Стабільна мапа API —
`lab/stable_local_api.json`; обмеження та явний список «не обіцяє» — у
[spec/16-UTILITY-AND-LOCAL-ENTRYPOINT-v0.md](spec/16-UTILITY-AND-LOCAL-ENTRYPOINT-v0.md).
Демонстрація й бенчмарк роблять нуль мережевих і нуль модельних викликів. SAIMAIL
**не** обіцяє автоматичне виявлення правди, надійність рецензента, примушування
JSON Schema провайдера, автоматичне просування чи листування, інтеграцію
Gmail/Slack/Outlook, провізіонування апаратних ключів чи нульові накладні витрати
протоколу.

### Тривалий локальний робочий простір (V2-01)

Практичний локальний робочий потік. Два робочі простори, дві тривалі ідентичності,
одне справжнє локальне повідомлення через окремі виклики процесів:

```
pip install "saimail[crypto]"
saimail-local init --workspace ws-a --seat SAIMAIL-A
saimail-local init --workspace ws-b --seat SAIMAIL-B
saimail-local identity --workspace ws-a --export-card a.card.json
saimail-local identity --workspace ws-b --export-card b.card.json
# обмінятися ПУБЛІЧНИМИ картками та зареєструвати обидві сторони (по одній команді)
saimail-local recipient add --workspace ws-a --alias bob --card b.card.json --peer-workspace ws-b
saimail-local recipient add --workspace ws-b --alias alice --card a.card.json --peer-workspace ws-a
# кожна команда нижче — окремий процес; стан зберігається на диску
saimail-local send --workspace ws-a --to bob --claim "one line for bob"
saimail-local inbox --workspace ws-b            # лише метадані, без payload
saimail-local open --workspace ws-b --envelope sha256:...
saimail-local reopen --workspace ws-b --envelope sha256:... # повторно прочитати відкрите повідомлення без зміни стану
saimail-local send --workspace ws-a --redeliver sha256:...   # точний replay -> DUPLICATE
saimail-local acceptance --root fresh-dir       # гарнітура PASS/FAIL однією командою
```

Ідентичність переживає перезапуски: `saimail-local identity` повертає ті самі
публічні відбитки після будь-якої кількості окремих викликів. Повторення точної
доставки — канонічний `DUPLICATE` (початковий `RECEIVED_AT` зберігається, і друге
непрочитане повідомлення не з'являється) — CLI не додає власного шару дедуплікації.
`open` вимагає точної ідентичності повідомлення, переміщує його до стану прочитаного
і ніколи не просуває; `reopen` дозволяє отримувачеві явно перечитати вже прочитане
повідомлення між сесіями без зміни тривалого стану чи дублювання бандлів; просування
лишається окремою дією. Машинно-читабельні результати — `LOCAL_WORKSPACE_COMMAND_1`
на команду і `LOCAL_WORKSPACE_RESULT_1` для гарнітури. `--json` працює на кожній
команді.

Лише локальна файлова система: доставка — явний шлях до робочого простору
отримувача, тож відправнику потрібен доступ на запис до нього. Без
Gmail/Slack/Outlook, без адаптера, без сервера чи демона, без віддаленого сервісу,
без семантичного рецензента, без автоматичного виявлення.

### Локальний альфа-кандидат (0.0.2a3)

Заморожений, локально доведений альфа-кандидат для перевірки повного тривалого
робочого простору без залежності від мережі:

```
pip install "saimail-0.0.2a3-py3-none-any.whl[crypto]"
saimail-local --version
```

Маніфест кандидата фіксує точну ідентичність паковання, доказ вмісту, обмеження
безпеки відповідно до режиму та правдивість інструментів релізу (відмова збирати
в історичний бандл a1 або перезаписувати будь-який заморожений кандидат);
`tools/local_alpha_release.py
verify --bundle <dir>` повторно перевіряє записані
хеші, а доказ вмісту wheel відмовляє кандидату без модуля зберігання, схеми
ідентичності v2, поверхні `--custody`/`custody status`/`custody migrate`, повідомлення
про перший запуск і — з `--require-product-delta` — продуктової поверхні P1/V4-01/V5-01.
Пошкоджений wheel або пошкоджений записаний хеш відхиляється (червона перевірка), а
скан приватності релізу (`tools/scan_local_alpha_privacy.py`) провалюється на
підсадженому маркері або підсадженому ключовому матеріалі. Історичні свідчення a2
живуть у `release/evidence/a2/`; поточні свідчення кандидата (перевірка встановленого
wheel, доказ Windows os-store, доказ міграції, відтворюваність, червоні перевірки
приватності/цілісності, матриця заяв і оцінка брами) живуть у `release/evidence/a3/`.
Повний контракт, сфера альфи, сфера платформеного доведення (CPython 3.11 на win32)
і список «не заявляє» — у
[spec/18-LOCAL-ALPHA-v0.md](spec/18-LOCAL-ALPHA-v0.md),
[spec/20-LOCAL-KEY-CUSTODY-v0.md](spec/20-LOCAL-KEY-CUSTODY-v0.md),
[spec/DECISIONS-D055.md](spec/DECISIONS-D055.md) та
[spec/DECISIONS-D056.md](spec/DECISIONS-D056.md).

**Працює:** встановити паковання; ініціалізувати тривалі робочі простори;
обмінятися публічними картками ідентичності; зареєструвати відомого локального
піра; локальне надсилання; перелічення скриньки (лише метадані) та обмежений
запит/тріаж скриньки (`P1`); явне відкриття; явне одноперегонне продовження
листування (`V4-01`); придушення дублікатів; тривалість між перезапусками;
необов'язковий GUI локального месенджера для робочого столу (`V5-01`, `saimail-gui`,
PySide6 поза extra `gui` — ніколи не базова залежність); raw (типове) зберігання
ідентичності; явне захищене зберігання `os-store`, де існує перевірений бекенд
облікових даних ОС, включно з міграцією зі збереженням відбитків; демонстрація FG-05;
бенчмарк FG-06; приймання V2-01; машинно-читабельні результати.

**Не існує:** віддалена доставка, інтеграція email-провайдерів, сервер, демон,
синхронізація акаунтів, автоматичне виявлення отримувачів, захищений типовий режим,
апаратне зберігання, ротація ключів, автоматичне відновлення, автоматичне листування,
загального призначення захищений месенджер.

**Попередження щодо зберігання (два режими):** типовий режим `raw` зберігає приватні
ключі ідентичності Ed25519/X25519 як сирі програмні файли в робочому просторі —
**не зашифровані в спокої**, а скопійована директорія робочого простору копіює
ідентичність. Явний opt-in `os-store` переміщує приватні ключі до сховища облікових
даних ОС і вилучає сирі байти з робочого простору, захищаючи **лише** від експозиції
через копіювання директорії робочого простору; він **не** захищає від шкідливого ПЗ
чи процесів, що працюють як той самий авторизований користувач, компрометації
адміністратора/ядра, апаратної атаки, фізичної присутності чи доказу людської
ідентичності, і не надає апаратного зберігання, ротації чи автоматичного відновлення.
Міграція OS-акаунта/хоста може залишити ключовий матеріал у пастці, а доказ бекенда
для цього кандидата є Windows-специфічним (`WinVaultKeyring`). Межі заяв:
[spec/20-LOCAL-KEY-CUSTODY-v0.md](spec/20-LOCAL-KEY-CUSTODY-v0.md).

**Попередження щодо корисності:** виміряний вердикт — `UTILITY_CONDITIONAL`. SAIMAIL
не універсально економить токени чи кошти; робочі потоки з помірною/високою частотою
відкриття нейтральні в межах проголошеної моделі тертя.

**Попередження альфи:** це обмежений локальний альфа-кандидат, не
продакшн-сервіс комунікації.

**Статус публікації:** побудова кандидата не означає, що паковання опубліковано.
`publication_status = NOT_PUBLISHED`; публікація — окрема явна дія оператора. Точний
wheel `0.0.2a2` зовнішньо доведено в справжньо окремому середовищі Linux / Python
3.13.5 (`release/evidence/a2/external_linux_verification.json`). Поточний wheel
`0.0.2a3` локально заморожено й доведено; його справжнє зовнішнє доведення **ще не
прийнято** (`READY_FOR_EXTERNAL_INSTALL_PROOF`), а зовнішнє доведення a2 ніколи не
успадковується. Авторизація публікації (G17) лишається відсутньою.

## Облікові дані SAIRoute

Один логічний хендл, provisionований один раз людиною, після чого його розв'язує
кожен агент, і жодному не доводиться знову вставляти ключ:

```
credential://9router/sairoute
```

Він розв'язується через локальне сховище облікових даних — на Windows це Windows
Credential Manager, а код перевіряє, що `keyring` справді вибрав `WinVaultKeyring`,
а не припускає це лише через успішний імпорт. Хост, чий keyring не може бути цим
сховищем, зазнає невдачі з `SAIROUTE_CREDENTIAL_BACKEND_UNSUITABLE` замість того,
щоб виглядати працюючим.

```
python tools/provision_sairoute_credential.py               # зберегти один раз
python tools/provision_sairoute_credential.py --check       # збережено? який бекенд?
python tools/provision_sairoute_credential.py               # знову = ротація
python tools/provision_sairoute_credential.py --delete      # видалити
python lab/saifren_run.py --out lab/out                     # звичайний живий прогін
```

Секрет вводиться в інтерактивному невідлунюючому промпті та підтверджується один
раз. Немає `--key`, немає `--secret` і немає шляху стандартного вводу: `echo SECRET |`
покладе облікові дані в історію shell, тобто в ту експозицію, яку сховище існує,
щоб усунути. Без TTY інструмент відмовляє з
`SAIROUTE_PROVISIONING_REQUIRES_TTY`.

**Звичайна жива команда не читає секрет із середовища** (D-019). Відсутні облікові
дані — `SAIROUTE_CREDENTIAL_NOT_PROVISIONED`, ніколи не мовчазний fall-through. Стара
змінна `SAIROUTE_API_KEY` досі працює, але лише коли її названо:

```
python lab/saifren_run.py --out lab/out --credential-source env
```

Той вибір записується в артефакт як `credential.source`, тож прогін, що використав
стару змінну, прямо це повідомляє. Жоден артефакт, звіт, рядок журналу чи виняток
ніколи не несуть самого значення.

Залежності оголошено в [pyproject.toml](pyproject.toml). Сама бібліотека не має
жодної: парсер — лише дані. Extra `test` встановлює все, що потрібно повному набору,
включно з токенізатором, — один контракт, тож рекламована команда є тією, що працює.
`tiktoken` зафіксовано, тож опубліковані співвідношення токенів залишаються
відтворюваними; він завантажує малі BPE-таблиці під час першого використання, але
ніколи ваги моделей.

Апаратне зберігання — окремий необов'язковий extra, який ніколи не встановлюється
під час виконання:

```
pip install -e ".[hardware-yubikey]"
python -m saimail.hardware_piv inspect          # строго лише для читання
python -m saimail.hardware_piv verify --device NAME --slot 9D
```

Без extra кожна апаратна точка входу відмовляє з
`HARDWARE_PROVIDER_UNAVAILABLE`; з extra, але без токена, ручна перевірка
повідомляється як `NOT_RUN_NO_HARDWARE`, ніколи не `PASS` і ніколи не `FAIL`. Обидві
команди недеструктивні: немає шляху provision, import, deletion чи reset, немає
автоматичного вибору слота і немає опції `--pin` — PIN вводиться лише в інтерактивному
промпті.

## Несучі правила

- **`message != memory`.** Тривала пам'ять вимагає просування, а просування є
  kind-обізнаним: свідчення для фактів і спостережень, умова фальсифікації для
  гіпотез, лише провенанс для цілей і цінностей.
- **Інформаційні, не конституційні.** Приватне повідомлення може сказати будь-що,
  але нічого не авторизує. Текст payload, що виглядає як команда, інертний.
- **Спостережувано, але приватно.** Вміст можна запечатати; трафік — ніколи.
- **Жодних заяв про намір.** Найсильніший вердикт про висловлювання —
  `CONTRADICTED`. Вердикту про людину немає.
- **Запис — авторитет.** Тріаж-фрейм декодовний, але ніколи не авторитетний, ніколи
  не свідчення і ніколи не реконструює те, що він опустив.

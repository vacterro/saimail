IMPORTANT ROADMAP CONTRACT CORRECTION

The current V4-01 roadmap text says the reply should reference the original record identity through existing SAILANG relation fields.

Do not implement that literally.

Existing SAILANG fields:

SUPPORTS
REFUTES
CON

are semantic relations between immutable statements.

They mean substantive things about the referenced record.

A generic correspondence reply does not necessarily:

support,
refute,
or conflict with

the original statement.

Using these fields merely to mean "this is a reply to that message" would corrupt the truth/semantic graph.

The existing SENV2 header already contains the correct neutral primitive:

REF

related record or prior envelope

P1 already indexes this field and exposes exact:

for generic correspondence continuation.

Do NOT automatically insert:

SUPPORTS
REFUTES
CON

into the reply record.

If an operator explicitly supplies a canonical SAILANG record that contains one of those semantic relations, preserve it because the author chose that meaning.

The reply mechanism itself must not invent it.

Update the V4-01 roadmap wording and new V4-01 specification to reflect this corrected contract.

This is a semantic correction inside the selected gate, not a separate ticket.

The original sender can therefore discover replies with:

without opening payloads.

This provides neutral correspondence linkage without changing SAILANG semantics or the wire format.

--------------------------------------------------
A1 — DO NOT USE FILE EXISTENCE AS EXPIRY AUTHORITY
--------------------------------------------------

Current `bundle_state()` effectively treats:

expired_tombstone(envelope_id).is_file()

as sufficient proof.

That is not sufficient.

If a tombstone exists, validate its metadata before returning EXPIRED or
EXPIRY_RECONCILIATION_REQUIRED.

Header-only scan MAY read the small receiver-owned tombstone JSON.

It must still never read `.senv` payload bytes.

Invalid tombstone:

-> EXPIRED_TOMBSTONE_CORRUPT

or a more precise existing named refusal

NOT:

EXPIRED

NOT:

INDEX_BODY_MISSING hidden by tombstone existence

--------------------------------------------------
A2 — BIND TOMBSTONE PATH TO ENVELOPE_ID
--------------------------------------------------

Fresh independent reproduction 2:

The file path is for ENVELOPE_ID X.

The JSON tombstone is structurally valid but contains:

envelope_id = Y
sender = another seat
kind = another kind

with recipient and received_at left compatible.

CURRENT exact redelivery of X:

-> DUPLICATE

This is wrong.

A tombstone located at:

expired/<seat>/<digest-of-X>.json

must mechanically assert:

tombstone.envelope_id == X

and the filename digest must correspond exactly to X.

Do not trust directory/file naming alone.
Do not trust the JSON field alone.

Require both to agree.

--------------------------------------------------
A3 — TOMBSTONE / INDEX BINDING
--------------------------------------------------

For a settled expired object with an index row, prove from metadata alone:

tombstone.envelope_id == index.envelope_id
tombstone.sender      == index.from
tombstone.recipient   == index.to
tombstone.kind        == index.kind
tombstone.received_at == index.received_at
tombstone.reason      == TTL_EXPIRED

The tombstone intentionally does not contain topic/key ids/created/ref, so do
not invent fields solely to reproduce the whole index.

The fields it DOES claim must agree.

If they do not:

EXPIRED_TOMBSTONE_CONFLICT

Do not skip the message.
Do not call it expired.
Do not resurrect it.

--------------------------------------------------
A4 — EXPIRED REDELIVERY
--------------------------------------------------

`_expired_dedup()` must require the tombstone to be bound to:

- this exact ENVELOPE_ID
- this receiver seat
- the persisted index identity
- the incoming verified header for every overlapping claimed field

At minimum require equality for:

envelope_id
sender/FROM
recipient/TO
kind/K
received_at against the existing index

A tombstone for another logical object must never suppress delivery merely
because somebody placed it under the incoming object's filename.

--------------------------------------------------
A5 — CANONICAL TOMBSTONE BYTES
--------------------------------------------------

The writer already emits canonical JSON.

Make the reader enforce the same canonical representation if that is consistent

raw == canonical_json(parsed_object)

Reject:
- duplicate keys
- noncanonical equivalent JSON
- malformed UTF-8
- unknown/missing fields

Do not introduce multiple accepted encodings for an immutable evidence object
unless an existing decision explicitly requires that.

--------------------------------------------------
B1 — RECOVER TOMBSTONE + BOTH
--------------------------------------------------

For:

valid tombstone
+
inbox X
+
read X

maintenance must first mechanically prove:

inbox == read as the same transport object

using the existing exact content-identity checks.

Then prove:

- live bundle verifies
- receipt matches tombstone RECEIVED_AT
- index matches the live object
- tombstone fields match live/index identity
- effective_ttl_seconds equals the policy implied by the signed live header and
  current receiver default used by this mailbox
- tombstone.expired_at is not before:
  received_at + effective_ttl

Only then finish expiry.

One successful `recover()` must leave:

tombstone/X
NO inbox/X
NO read/X
state = EXPIRED

Do not require a second call.

A process crash DURING that cleanup may of course leave one body copy for the
next recovery; that is crash recovery, not successful-return semantics.

--------------------------------------------------
B2 — SWEEP MUST NOT CREATE TOMBSTONE + LIVE COPY FROM BOTH
--------------------------------------------------

Current `sweep_expired()` with:

inbox/X
+
read/X
+
no tombstone

selects one bundle through effectively:

inbox or read

and expires only that copy.

Fresh independent reproduction:

sweep result:
expired = 1

post-state:
tombstone/X
+
read/X

This is not a completed expiry.

Fix it.

Because sweep is already a maintenance operation and may read `.senv`, preferred
minimal behavior:

1. detect BOTH
2. mechanically prove the two bundles are identical with existing
   `_check_reconcilable`
3. resolve the duplicate crash copy while preserving one complete live body
4. evaluate TTL on the authoritative remaining body
5. publish tombstone
6. delete the final body

Alternative acceptable behavior:

BOTH
-> named RECONCILIATION_REQUIRED
-> caller must run recover first

but do not claim the envelope expired and leave a live body behind.

Prefer convergence in sweep if it remains simple and preserves one fixed lock
order.

--------------------------------------------------
B3 — TOMBSTONE ELIGIBILITY DURING CRASH RECOVERY
--------------------------------------------------

When a tombstone coexists with a body, the body still exists, so recovery has
enough evidence to verify that the tombstone could legitimately have been
created.

Recompute:

expected_ttl =
effective_ttl_seconds(verified_header, receiver_default)

expected_expires_at =
received_at + expected_ttl

Require:

tombstone.effective_ttl_seconds == expected_ttl

and:

tombstone.expired_at >= expected_expires_at

A structurally valid tombstone must not be able to cause premature body deletion.

This check is required only while the body still exists.

For a settled body-less historical expiry, the signed TTL header is intentionally
gone; use the metadata/index integrity contract from Target A and do not invent
missing payload evidence.

--------------------------------------------------
B4 — NO BODY LOSS ON CONFLICT
--------------------------------------------------

Any disagreement among:

tombstone
index
receipt
inbox
read
verified SENV2 header

Named outcomes may reuse:

EXPIRY_STATE_CONFLICT

READ_BUNDLE_CONFLICT
INDEX_ROW_CONFLICT

Do not normalize conflicting evidence.

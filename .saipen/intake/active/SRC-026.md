TARGET A — FREEZE THE T-7 EXECUTION CONTRACT
======================================================================

Record one explicit decision before implementing TTL code.

The six previously blocked questions are decided below.

--------------------------------------------------
A1 — DEFAULT TTL
--------------------------------------------------

Receiver default EPHEMERAL retention:

14 days

This is intentionally inside the previously declared 7–30 day range.

The Post Office should expose the receiver-owned default as configuration with:

default_ttl = 14 days

Allowed receiver configuration range for v0:

7 days <= default_ttl <= 30 days

Do not silently accept an invalid receiver policy.

--------------------------------------------------
A2 — ENVELOPE TTL SEMANTICS
--------------------------------------------------

The signed envelope `TTL:<nD|nH>` is NOT permission for the sender to force the
receiver to retain data longer than receiver policy.

Treat the sender TTL as a RETENTION CEILING.

Effective v0 TTL:

if envelope TTL absent:
    effective_ttl = receiver default_ttl

if envelope TTL present:
    effective_ttl = min(parsed envelope TTL, receiver default_ttl)

Therefore:

receiver default 14D
header absent
-> 14D

receiver default 14D
header TTL 7D
-> 7D

receiver default 14D
header TTL 30D
-> 14D

The sender may request shorter retention.

The sender may not force longer retention.

This preserves receiver authority over storage.

Existing SENV2 syntax is unchanged.

Do not introduce a new wire version.

Existing parser currently accepts zero-valued TTL such as 0D/0H.

Do not change SENV2 syntax in T-7.

For T-7 semantics:

effective TTL 0
-> immediately eligible on the first explicit sweep at or after RECEIVED_AT

Do not auto-delete during delivery.

--------------------------------------------------
A3 — EXPIRY CLOCK
--------------------------------------------------

Expiry is receiver-local:

expires_at =
RECEIVED_AT + effective_ttl

Never:

CREATED + TTL

Never:

current time relative to sender CREATED

CREATED remains sender-authored metadata only.

Eligibility:

now >= expires_at

Use UTC receiver-local instants.

--------------------------------------------------
A4 — SWEEP TRIGGER / AUTHORITY
--------------------------------------------------

T-7 v0 sweep is EXPLICIT MAINTENANCE ONLY.

PostOffice.sweep_expired(now=...)

Do NOT run TTL sweep automatically inside:

Do NOT add:

The caller/operator decides when maintenance runs.

This keeps T-7 deterministic and testable.

Do not add claim/payload/evidence content.

`index.jsonl` remains append-only and unchanged.

B2 — IMMUTABLE TOMBSTONE
--------------------------------------------------

Use the existing immutable publication discipline.

Required order:

1. verify candidate bundle mechanically
2. prove TTL eligibility
3. construct complete canonical tombstone bytes
4. publish tombstone atomically with NO OVERWRITE
5. fsync as appropriate
6. only then delete the live inbox/read bundle
7. fsync the state directory

Never:

delete body
-> then attempt tombstone

The fact of existence must survive every crash window.

Existing identical tombstone:
-> idempotent

Existing different tombstone for same ENVELOPE_ID:
-> named conflict
-> do not delete body
-> do not overwrite winner

--------------------------------------------------
B3 — VERIFY BEFORE DESTRUCTIVE EXPIRY

- receipt ENVELOPE_ID matches
- index has exactly one matching row
- index RECEIVED_AT equals receipt RECEIVED_AT
- TTL eligibility is true

Do not delete a corrupted object merely because its filesystem timestamp is old.

Filesystem mtime/ctime are NOT TTL authority.

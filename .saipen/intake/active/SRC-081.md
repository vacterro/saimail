MILESTONE 2 — BOUNDED QUERY MODEL

Do not implement P1 by calling:

office.read_index()

and materializing an arbitrarily large inbox.

The Post Office already has bounded streaming machinery:

* byte-offset cursor validation;
* sequential index-row parsing;
* scan budgets;
* continuation without re-reading the prefix.

Reuse the same invariant and implementation logic where appropriate.

Do not misuse PostOfficeSession.scan semantics directly if doing so would inherit:

* unread-only behavior;
* HeaderInterest decisions;
* attention merging;
* model recommendation semantics.

P1 needs a separate metadata-query operation.

Prefer a small public PostOffice query/read surface that reuses the same bounded streaming primitives.

Avoid duplicating a second incompatible cursor implementation.

Required bounds:

* caller-declared or safe-default row scan budget;
* hard maximum scan budget;
* explicit rows_examined;
* explicit continuation cursor when more index data remains.

A cursor must be opaque or mechanically validated and must never point inside an index row.

Invalid, negative, non-boundary, or past-EOF cursors must fail with the existing BAD_CURSOR contract where possible.

Do not derive continuation by rescanning from row zero.

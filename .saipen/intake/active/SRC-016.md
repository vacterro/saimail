A2 — REJECT THE TWO INCOMPLETE FORMS
--------------------------------------------------

Do NOT adopt:

1. full current canonical unsigned header as AEAD AAD

because that header contains CIPHER_HASH:

ciphertext depends on AAD

which is circular.

Do NOT adopt:

because key identity and seat identity are distinct.

The current KeyRegistry permits the same accepted key fingerprint to appear
under more than one seat.

Therefore:

FROM_KID alone
does not cryptographically bind
FROM + FROM_KID

as one identity.

Required minimum sender identity:

FROM
+
FROM_KID

--------------------------------------------------
A3 — PREFERRED MINIMAL SENV2 CONSTRUCTION
--------------------------------------------------

Prefer the smallest acyclic repair:

FORMAT:
SENV2

SIGNATURE DOMAIN:
SAIMAIL-SENV2-SIGNATURE\0

HKDF DOMAIN:
version-separate the payload key derivation, e.g.

SAIMAIL-SENV2-PAYLOAD-KEY\0

Do not use the SENV1 HKDF domain unchanged across the wire transition.

AEAD associated data must cryptographically bind the sender identity.

Preferred minimal conceptual form:

AEAD_AAD =
SAIMAIL-SENV2-SENDER-BINDING\0
||
canonical_sender_identity

where canonical_sender_identity is exactly:

FROM:<seat>\n
FROM_KID:<full fingerprint>\n

Use UTF-8, LF, final LF, no BOM, fixed field order.

The exact representation must be one-to-one and documented.

This is deliberately narrower than the entire header.

It closes D-033 without accidentally creating the CIPHER_HASH cycle.

--------------------------------------------------
A5 — STATE THE GUARANTEE PRECISELY
--------------------------------------------------

Do NOT claim:

"the recipient proves the signer personally performed encryption"

or:

"the sender authored the plaintext"

The correct property is narrower.

Required guarantee:

An existing SENV2 ciphertext sealed under sender identity:

FROM = A
FROM_KID = K_A

cannot be relabelled to:

FROM = B
FROM_KID = K_B

and successfully opened merely because B is another accepted signing peer.

Changing the bound sender identity changes AEAD authentication context and the
old ciphertext refuses.

Still NOT proved:

- plaintext authorship
- originality
- first transmission
- that one physical process performed both encryption and signing
- that a sender who legitimately obtained plaintext did not reseal it

Preserve:

CONTAINER SENDER != PAYLOAD AUTHOR

unless payload-level evidence proves otherwise.

--------------------------------------------------

--------------------------------------------------

-> CIPHER_HASH comparison
-> resolve accepted sender key
-> verify Ed25519 signature
-> mint VerifiedEnvelope
-> resolve accepted recipient seat/key/private-key binding
-> derive SENV2 payload key
-> reconstruct exact SENV2 sender-binding AAD
-> AEAD decrypt
-> return inert bytes

Changing bound sender identity must cause AEAD authentication failure.

Do not reinterpret that as a signature failure.

-> DECRYPTION_FAILED

Do not simply delete the old finding.

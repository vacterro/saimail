FRESH P1 REPRODUCTION A  BACKDATED ACK BYPASSES BUDGET
======================================================================

Current public API accepts caller-supplied `now`.

Fresh independent reproduction:

budget:
max_presentations = 1
period_seconds = 86400

candidate A
candidate B

reserve A:

reserve_next(
    now = 2026-09-19T12:00:10Z
)

-> RESERVED

Then ACK the same reservation with:

ack_presented(
    reservation_id,
    now = 2020-01-01T00:00:00Z
)

CURRENT:

-> ACKED
-> PRESENTED_AT = 2020-01-01T00:00:00Z

Now query at the real 2026 logical receiver time:

budget_state(
    now = 2026-09-19T12:00:11Z
)

CURRENT:

consumed = 0
available = 1

Then:

reserve_next(
    now = 2026-09-19T12:00:12Z
)

CURRENT:

candidate B -> RESERVED

Therefore:

one real presentation
+
backdated caller timestamp
=
zero budget consumption

This violates D-044.

======================================================================
FRESH P1 REPRODUCTION B  CALLER CAN EXPIRE A LIVE LEASE
======================================================================

Reserve candidate A at:

2026-09-19T12:00:00Z

with default lease:

LEASE_UNTIL =
2026-09-19T12:05:00Z

Before that lease has actually expired, call:

reserve_next(
    now = 2099-01-01T00:00:00Z
)

CURRENT:

the existing live lease is treated as expired

and a NEW reservation is returned.

Therefore two presentation actors may concurrently believe they own the same
scarce attention opportunity.

The public caller can currently advance receiver time arbitrarily.

This defeats the concurrency invariant even though the OS lock itself works.

FRESH AUTHORITY REPRODUCTION C  ENQUEUED_AT IS CALLER-CONTROLLED
======================================================================

Current admission takes a fully formed public AttentionCandidate containing:

ENQUEUED_AT

Example:

candidate REAL:
ENQUEUED_AT = 2026-09-19T12:00:00Z

candidate FORGED_OLD:
ENQUEUED_AT = 2000-01-01T00:00:00Z

same allocation.

Admit REAL first.
Admit FORGED_OLD second.

CURRENT:

reserve_next(...)
-> FORGED_OLD wins

because ordering correctly obeys ENQUEUED_AT,
but ENQUEUED_AT was not actually minted by the queue.

D-044/spec state:

ENQUEUED_AT = receiver-owned UTC instant

That must be mechanically true at the admission boundary.

======================================================================
TARGET A  QUEUE OWNS OPERATION TIME
======================================================================

The queue already has the correct architectural seam:

AttentionQueue(..., clock=...)

Use it.

Public production operations must obtain receiver time from:

self.clock

not from a caller-provided timestamp.

--------------------------------------------------
A1  REMOVE PUBLIC TIME OVERRIDES
--------------------------------------------------

Public APIs must no longer accept arbitrary operation time for:

reserve_next
ack_presented
budget_state

and any other externally reachable transition whose semantics depend on
receiver time.

Preferred public forms:

reserve_next()

ack_presented(reservation_id)

budget_state()

release(reservation_id)

They use the configured queue clock.

Tests requiring deterministic time must inject a deterministic clock into the
AttentionQueue constructor.

Do NOT retain:

reserve_next(now=...)
ack_presented(..., now=...)
budget_state(now=...)

as public authority-bearing escape hatches.

If compatibility requires a private/internal helper taking an explicit instant,
keep it private and never expose it as the supported production API.

--------------------------------------------------
A2  CLOCK TEST SEAM
--------------------------------------------------

Preserve deterministic tests through the constructor clock seam.

Implement/use a test clock that can be explicitly advanced by the test.

Conceptually:

clock = MutableReceiverClock("2026-09-19T12:00:00Z")

queue = AttentionQueue(..., clock=clock)

clock.set(...)
queue.reserve_next()

The test fixture may control the receiver clock.

The production caller may not provide a per-operation timestamp.

This distinction matters.

--------------------------------------------------
A3  ONE CLOCK READ PER TRANSITION
--------------------------------------------------

Each state-changing operation should resolve receiver NOW once after acquiring
the appropriate operational context and use that same instant throughout the
transition.

Do not call the clock repeatedly and allow:

reserved_at != lease arithmetic base

or:

validation time != receipt time

inside one transition.

A read-only budget query likewise uses one resolved instant.

Checkpoint.

======================================================================
TARGET B  TEMPORAL INVARIANTS / BUDGET BYPASS CLOSURE
======================================================================

Removing caller `now` closes the direct API exploit, but transition invariants
must still fail closed if the receiver clock regresses.

--------------------------------------------------
B1  ACK CANNOT PRECEDE RESERVATION
--------------------------------------------------

For a matched active reservation require:

PRESENTED_AT >= RESERVED_AT

If receiver NOW is earlier than RESERVED_AT:

refuse with a named error, e.g.:

ATTENTION_CLOCK_REGRESSION

Do not:

- publish a receipt
- remove the lease
- consume/release budget incorrectly

The live reservation remains intact.

--------------------------------------------------
B2  ACK STILL REQUIRES ACTIVE LEASE
--------------------------------------------------

Keep:

PRESENTED_AT < LEASE_UNTIL

for an ordinary successful ACK.

At:

now >= lease_until

the reservation is expired.

Do not allow a late ACK to resurrect it.

Existing semantics may remain:

ATTENTION_RESERVATION_EXPIRED

--------------------------------------------------
B3  PRESENTED RECEIPT TEMPORAL VALIDITY
--------------------------------------------------

When loading/validating a presented receipt together with its candidate and
known reservation history where available, do not accept impossible receiver
time relationships silently.

At minimum the transition that creates a receipt must guarantee:

reserved_at <= presented_at < lease_until

Do not invent historical reservation data after the lease has correctly been
removed.

The immutable receipt does not need to grow new fields solely for this target.

--------------------------------------------------
B4  FUTURE PRESENTED RECEIPTS
--------------------------------------------------

A valid existing receipt whose PRESENTED_AT is later than current receiver NOW
because the system clock moved backward must fail safe with respect to budget.

It must never be treated as:

outside the rolling window / free capacity

Preferred minimal behavior:

future PRESENTED_AT counts as consuming attention

or:

named clock-regression refusal

but NEVER:

available budget

Record the exact choice additively if D-044 needs clarification.

Do not silently repair immutable timestamps.

--------------------------------------------------
B5  LEASE CLOCK REGRESSION
--------------------------------------------------

If current receiver NOW is earlier than a lease's RESERVED_AT:

do not treat the lease as expired.

Prefer:

ATTENTION_CLOCK_REGRESSION

because the receiver clock moved behind durable receiver state.

Do not mint another reservation.

--------------------------------------------------
B6  RED/GREEN CONTROL
--------------------------------------------------

Required pre-fix reproduction:

reserve at 2026
ACK at 2020
-> ACKED
-> consumed 0
-> second RESERVED

Post-fix:

the same behavior must be impossible through the public API.

Additionally force the injected test clock backward:

clock -> 2020
ACK

-> ATTENTION_CLOCK_REGRESSION
-> no receipt
-> original lease preserved

TARGET C  ADMISSION MINTS ENQUEUED_AT
======================================================================

Receiver-owned ordering is only meaningful if the receiver queue actually
mints the receiver timestamp.

--------------------------------------------------
C1  SEPARATE ADMISSION REQUEST FROM DURABLE RECORD
--------------------------------------------------

Do not require a caller to supply ENQUEUED_AT when requesting admission.

Preferred minimal API:

queue.admit_receiver_candidate(
    source_kind=...,
    source_ref=...,
    allocation=...,
    deferral_policy=...
)

TO_HUMAN comes from:

queue.human_id

ENQUEUED_AT comes from:

queue.clock()

The result contains the complete immutable AttentionCandidate.

Alternative:

introduce a small AttentionCandidateRequest / Draft type containing no
receiver timestamp.

Do NOT make the caller mint the durable record's receiver-owned time.

--------------------------------------------------
C2  ATTENTIONCANDIDATE MAY REMAIN THE DURABLE TYPE
--------------------------------------------------

AttentionCandidate may remain publicly readable and parser-constructible as the
immutable durable representation.

But the receiver admission API must not accept an arbitrary pre-stamped
AttentionCandidate as sufficient authority for new durable admission.

A caller-created object with:

ENQUEUED_AT = 2000

must not let the caller jump the receiver queue.

--------------------------------------------------
C3  FIRST ADMISSION TIME STANDS
--------------------------------------------------

Preserve current identity:

candidate_id =
TO_HUMAN
+
SOURCE_KIND
+
SOURCE_REF

ENQUEUED_AT remains outside identity.

-> durable ENQUEUED_AT = T1

-> IDEMPOTENT
-> existing candidate returned
-> ENQUEUED_AT remains T1

Changed policy:

-> ATTENTION_CANDIDATE_CONFLICT

No rewrite.

--------------------------------------------------
C4  TO_HUMAN IS ALSO QUEUE-OWNED AT ADMISSION
--------------------------------------------------

The supported admission API should not require a caller to redundantly provide:

TO_HUMAN

The queue already owns:

self.human_id

This removes another unnecessary caller-controlled copy of receiver identity.

Persisted parsing still validates TO_HUMAN normally.

C5  ORDERING

Ordering remains exactly:

then CANDIDATE_ID ascending

Do not change D-044 ordering.

Only fix who is allowed to mint ENQUEUED_AT.

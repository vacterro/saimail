----------------------------------------------------------------------
A6 — DEFERRAL POLICY
----------------------------------------------------------------------

Closed set:

QUEUE_AND_CONTINUE
BLOCK_UNTIL_HUMAN
ESCALATE_AND_HALT

These describe what the CALLER should do when attention cannot currently be
granted.

B-011 itself must NOT:

- stop SAIPEN
- mutate STATE
- halt a process
- create a ticket

It returns an explicit outcome.

Semantics:

QUEUE_AND_CONTINUE
-> candidate remains queued
-> caller may continue unrelated work

BLOCK_UNTIL_HUMAN
-> candidate remains queued
-> caller receives ATTENTION_BLOCKED

ESCALATE_AND_HALT
-> candidate remains queued
-> caller receives ATTENTION_HALT_REQUIRED

The latter is a signal to the caller.

It is not an automatic process kill or SAIPEN mutation.

----------------------------------------------------------------------
A7 — BUDGET
----------------------------------------------------------------------

Receiver-owned default:

MAX_PRESENTATIONS = 1

PERIOD_SECONDS = 86400

Use a rolling receiver-time window.

Do NOT define "today" in protocol v0.

That avoids timezone/calendar/DST ambiguity.

Future UI may display:

YOU HAVE 1 MESSAGE WORTH YOUR ATTENTION TODAY

but the protocol contract remains a rolling budget.

Receiver configuration may choose another positive period.

MAX_PRESENTATIONS = 0 is valid.

It means:

NO HUMAN ATTENTION MAY BE CONSUMED THROUGH THIS QUEUE

It is not a configuration error.

----------------------------------------------------------------------
A8 — NO FORCED MESSAGE
----------------------------------------------------------------------

- queue is empty
- no eligible candidate exists
- budget is unavailable

NO_MESSAGE

Never synthesize a message merely because a period has started.

----------------------------------------------------------------------
A9 — NO BUDGET BYPASS
----------------------------------------------------------------------

In v0 NO allocation automatically bypasses the attention budget.

Even:

CRITICAL_RECOVERY

does not silently create an extra human-facing delivery.

If its deferral policy is:

ESCALATE_AND_HALT

the caller may halt until human attention becomes available.

This preserves scarcity without silently losing a critical condition.

Any future emergency bypass requires a new explicit decision.

----------------------------------------------------------------------
A10 — DELIVERY IS TWO-PHASE
----------------------------------------------------------------------

Do NOT consume the durable human-attention budget merely because a scheduler
selected a candidate.

External presentation is a side effect.

Use:

RESERVE
then
ACK_PRESENTED

Flow:

queued candidate
-> reserve one attention slot
-> caller presents it
-> caller explicitly ACKs successful presentation
-> durable budget consumption recorded

If presentation fails:

release reservation

or let its bounded lease expire.

This avoids:

"process crashed after durable DELIVERED record but before the human ever saw
anything"

being silently treated as successful attention consumption.

----------------------------------------------------------------------
A11 — RESERVATION
----------------------------------------------------------------------

A reservation is receiver-local operational state.

It must contain at least:

reservation_id
candidate_id
reserved_at
lease_until

It is not immutable historical evidence.

It may expire or be explicitly released.

An ACTIVE reservation provisionally consumes one budget slot so two concurrent
workers cannot both reserve the final available slot.

----------------------------------------------------------------------
A12 — ACK
----------------------------------------------------------------------

ACK_PRESENTED creates immutable receiver evidence:

candidate_id
reservation_id
presented_at

Budget consumption is based on PRESENTED_AT.

A reservation may be ACKed only once.

Wrong/expired reservation:
refuse.

Repeated exact ACK:
idempotent.

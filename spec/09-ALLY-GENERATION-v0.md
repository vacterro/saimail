# ALLY_ADVICE GENERATION v0

Normative decision: [D-047](DECISIONS.md). This specification defines the
bounded generation and semantic-review layer above the completed B-012 object
and corridor ([ALLY_ADVICE v0](08-ALLY-ADVICE-v0.md)). It adds no SAILANG kind,
no encryption format and no model adapter.

## Purpose and authority

Autonomous ALLY_ADVICE generation is only reachable through one bounded,
caller-supplied corpus and one independent semantic review. The layer exists so
that the open questions D-046 deliberately left open — whether the cited
evidence supported the observation, whether inconvenient examples were
ignored, whether counterevidence is meaningful, whether the inference is
secretly a motive claim, whether the prose flatters or pressures — are answered
by a review boundary that can be named, bound and refused, not by regex
theatre or a confidence number.

```
GENERATOR_OUTPUT != FACT
REVIEWER_PASS != TRUTH
REVIEWER_IDENTITY != AUTHORITY
MODEL_AGREEMENT != TRUTH
EVIDENCE_EXISTS != EVIDENCE_SUPPORTS_CLAIM
EVIDENCE_REF = EVIDENCE_ARTIFACT_IDENTITY
EVENT_REF = CALLER_DECLARED_UNDERLYING_OPERATIONAL_EVENT
EVENT_REF_IS_TRUTH = false
DISTINCT_EVENT_REFS != SEMANTIC_PATTERN_PROOF
STRUCTURAL_PATTERN != SEMANTIC_PATTERN
SEMANTIC_REVIEW_REPORT = DATA_NOT_INVOCATION_PROOF
REVIEW_EVIDENCE_REFS = REVIEWER_CITED_SOURCES_NOT_SEMANTIC_PROOF
NO_ADVICE is a first-class successful result
```

The system must prefer silence over weak personal theory. Zero advice is a
valid successful state.

## Explicit source corpus

The generation layer never discovers history. The caller constructs, in
memory, one `ReflectionCorpus`; the layer may inspect only the objects in it
and performs no implicit access to memory, conversation history, mail,
calendar, filesystem, networks, stores, profiles or SAIPEN state. No
production corpus store exists.

Each immutable `ReflectionItem` carries:

- `EVIDENCE_REF` — canonical `sha256:<64 lowercase hex>`; identity of one
  supplied evidence artifact;
- `EVENT_REF` — canonical `sha256:<64 lowercase hex>`; identity of the
  underlying operational occurrence/group that the corpus builder asserts this
  artifact belongs to. Several artifacts may share one `EVENT_REF`; in v0 one
  artifact belongs to exactly one declared event, and multi-event evidence
  graphs are not implemented — a corpus builder facing an artifact that
  describes several events splits it or narrows the artifact before admission;
- `SOURCE_DOMAIN` — exactly `PROJECT_OPERATIONAL`;
- `OBSERVED_AT` — canonical UTC, informational only;
- `OBSERVED_SCOPE` — explicit bounded project scope;
- `CONTENT` — bounded UTF-8 evidence text supplied for reasoning.

`EVENT_REF` is supplied explicitly by the authorized corpus builder. It is not
inferred from `CONTENT`, not generated by a model, not derived from
`OBSERVED_AT`, not the `EVIDENCE_REF`, and no automatic clustering, embedding
similarity, timestamp-window, filename or ticket heuristic mints it. It is an
assertion, not truth: `EVENT_REF_IS_TRUTH = false`. The declaration says only
that the builder asserted these artifacts belong to this event; it does not
mechanically prove the events are genuinely independent, that the grouping is
objectively correct, that the event happened, or that two event refs cannot
describe the same real occurrence.

`SOURCE_DOMAIN_DECLARATION != CONTENT_PROOF`: the source-domain marker is an
explicit caller assertion, never inferred from prose, and v0 accepts only
operational/project reflection material. Health, mental health, religion,
politics, sexual life, relationships, finances, criminal/legal history,
biometrics, unrelated private communication and personality profiling are out
of scope for autonomous generation; the layer does not pretend to detect them
with a classifier.

Bounds: at most 64 items, at most 8192 UTF-8 bytes per item content, at most
131072 bytes of total content. Overflow refuses with a named corpus-bound
error. Nothing is silently truncated.

The corpus has one domain-separated `CORPUS_ID` bound to the ordered item
identities, exact event declarations, exact scopes, exact content bytes and
source-domain declarations. Ordering is normalized deterministically (evidence
ref ascending); caller order never becomes semantic priority and `EVENT_REF`
never changes artifact sort order, only identity and pattern eligibility.
Generator and reviewer receive the same normalized corpus. Changing one item
byte, one scope, one declaration or one event grouping invalidates the identity
and every review bound to it. Corpus plaintext is never persisted merely to
obtain the identity.

## Generator contract

`AllyAdviceGenerator.generate(corpus) -> GeneratorResult` returns exactly one
of:

```
NO_ADVICE
CANDIDATE(AllyAdvice)
```

No third state carries a confidence score, ranking, multiple competing letters
or hidden priority. The candidate must already satisfy the full B-012
canonical and structural contract; there is no weaker draft schema. Every
evidence ref in `OBSERVED` and `COUNTEREVIDENCE` must exist in the exact
supplied corpus: a candidate citing an outside ref refuses with
`ALLY_GENERATED_REF_OUTSIDE_CORPUS` before any reviewer call. Existence is
resolved through the existing B-012 boundary
(`resolve_ally_evidence` + a corpus-backed `EvidenceResolver`), which proves
only that the cited object is in this corpus — never that it supports the
statement.

One orchestration call performs at most one generator invocation and at most
one reviewer invocation; there is no retry, prompt mutation, self-refinement
or review-driven optimization loop. A provider exception maps to a named
generation failure and is never reinterpreted as `NO_ADVICE`: `NO_ADVICE` is a
deliberate "nothing worth proposing"; `ERROR` is "generation could not be
performed". The reviewed type-state is reachable only through the actual
review invocation proof below; a report-only path does not exist.

## Distinct-event recurrence floor

Artifact count is not event count. For an autonomously generated candidate,
`OBSERVED` evidence refs are mapped through the exact corpus to their declared
`EVENT_REF` values and must span at least `MIN_DISTINCT_OBSERVED_EVENTS = 2`
distinct declared events before any semantic reviewer invocation. Otherwise the
orchestration refuses with `ALLY_GEN_INSUFFICIENT_DISTINCT_EVENTS` and the
reviewer call count is zero: no `SemanticallyReviewedAllyAdvice`, no letter, no
retry. `COUNTEREVIDENCE` is not measured by this floor; it may refer to one of
the observed events, another event, or span several events, and its adequacy
stays the reviewer's judgement.

The floor sits beside the existing B-012 artifact requirements, never instead
of them: a generated candidate still needs at least two observations and at
least three distinct observed evidence refs, and the manual B-012 object
contract is unchanged. Three refs from one declared event are refused; three
refs spanning two declared events are structurally eligible — and that only
establishes more than one declared occurrence, never a real pattern.
`DISTINCT_EVENT_REFS != SEMANTIC_PATTERN_PROOF`. The generator prompt states
the rule and the reviewer prompt states that artifacts sharing one `EVENT_REF`
count as one declared event, but prompt compliance is not authority: the
mechanical gate decides.

## Independent semantic review

`AllyAdviceSemanticReviewer.review(evidence_resolved_advice, corpus) ->
SemanticReviewReport` is a separate invocation boundary. It receives the exact
generated candidate and the full normalized corpus — never generator
chain-of-thought, hidden reasoning or a scratchpad. `REVIEWER_PASS != TRUTH`;
separate model identity is useful diversity but not proof of correctness.
Hidden chain-of-thought is never requested, stored or transported; the
reviewer returns only a bounded structured verdict and concise rationale.

Exactly eight dimensions are reviewed, each with exactly `PASS`, `FAIL` or
`UNKNOWN`. No score, probability, stars or weighted total:

| Dimension | Reviewer asks |
|---|---|
| `OBSERVATION_SUPPORT` | Does the bounded supplied corpus reasonably support the `OBSERVED` statements? A reviewer claim, not a truth promotion; the reviewer cites the corpus refs it relied on. |
| `COUNTEREVIDENCE_ADEQUACY` | Does the candidate's `COUNTEREVIDENCE` meaningfully reflect material evidence in the full corpus that weakens or limits the inference? The reviewer saw the bounded corpus, not the world. |
| `SCOPE_DISCIPLINE` | Do the observations stay inside the supplied scopes? Three decisions in one project are not all software projects; last month is not always; one queue is not all queues. Scope widening fails. |
| `NO_MOTIVE_INFERENCE` | Does the prose avoid unsupported psychological-cause claims ("you do this because you fear losing control")? Operational interpretation is allowed; motive inference is not. |
| `NO_FLATTERY` | Does the letter avoid recipient-directed praise that is not needed to communicate the observed pattern? Keywords are test fixtures only; the semantic decision belongs to the reviewer. |
| `NO_COMPLIANCE_PRESSURE` | Does the prose respect `GUIDANCE_STATUS = PROPOSAL` and `AGENCY = RECIPIENT_DECIDES` — no "you must", "trust me", "the correct choice is", no implication that a good recipient complies? |
| `UNCERTAINTY_ADEQUACY` | Does `UNCERTAINTY` state the actual limitations of sample, scope, interpretation and counterexamples rather than a generic "I may be wrong"? |
| `RECIPIENT_AGENCY` | Does the letter leave agreement optional — no change required or consider X, never "a smart recipient would comply"? |

Fail-closed: every dimension must be `PASS`. Any `FAIL` or `UNKNOWN`
produces `REJECTED`, no generated `HUMAN_PRIVATE` object, no rewrite, no
second attempt and no attention candidate. A reviewer failure to answer is
`UNKNOWN`, and `UNKNOWN` never becomes `PASS`.

The bounded immutable `SemanticReviewReport` binds `CANDIDATE_ID`,
`CORPUS_ID`, `RUBRIC_VERSION`, all eight verdicts and a bounded rationale per
dimension (at most 1024 UTF-8 bytes each, 8192 total) with optional cited
corpus refs. Missing, unknown or duplicate dimensions refuse; any ref outside
the corpus refuses. Model hidden reasoning never appears in the report, and no
durable plaintext review archive exists.

The report is data, never proof that an invocation happened. An
`OBSERVATION_SUPPORT` or `COUNTEREVIDENCE_ADEQUACY` verdict of `PASS` must
cite at least one evidence ref (`ALLY_GEN_REVIEW_EVIDENCE_REQUIRED`
otherwise): the reviewer claims to have assessed supplied evidence, and an
evidence-free `PASS` leaves no auditable trace of what it relied on. Every
cited ref must belong to the exact corpus, and a cited ref means only "the
reviewer says this source informed the verdict" — never proof that the source
semantically entails it (`REFERENCE_EXISTS != REFERENCE_SUPPORTS_CLAIM`).
Purely prose-semantic dimensions (`SCOPE_DISCIPLINE`, `NO_MOTIVE_INFERENCE`,
`NO_FLATTERY`, `NO_COMPLIANCE_PRESSURE`, `UNCERTAINTY_ADEQUACY`,
`RECIPIENT_AGENCY`) may stay evidence-free; `FAIL` and `UNKNOWN` are never
mechanically forced to cite, but when refs are present the corpus-membership
rule applies.

## Reviewed type-state

`SemanticallyReviewedAllyAdvice` is minted only through an actual review
invocation. `run_semantic_review(candidate, corpus, reviewer)` validates the
exact B-012 `EvidenceResolvedAllyAdvice` and the exact corpus, invokes
`reviewer.review` exactly once, validates the returned report, and mints a
non-transferable `ReviewInvocationResult` bound to the exact candidate, corpus
and report; `approve_semantic_review` accepts only that proof. A
caller-constructed `SemanticReviewReport` is data and never satisfies the
boundary (`CALLER_CONSTRUCTED_REPORT_CAN_MINT_REVIEWED_STATE = false`).

Approval additionally requires that every candidate ref belongs to the
corpus, the report's candidate and corpus identities match exactly, the rubric
matches and all eight dimensions are `PASS`. The constructor-only mint pattern
is the one B-012 already uses: direct construction and `dataclasses.replace`
transplant refuse for both the invocation proof and the reviewed type-state, a
changed candidate or corpus invalidates the proof, and no mint token is
retained. A reviewer fault or a non-report return mints no invocation proof
and no reviewed state; one run performs at most one reviewer invocation, and
rejection never triggers a second attempt.

The type means only this: one bounded semantic review invocation found no
listed disqualifier in this exact candidate against this exact supplied corpus
under this rubric. It does not mean good, true, safe, best or novel advice, and
it creates no truth rung, evidence, knowledge or promotion.

`NOVELTY = UNRESOLVED_FUTURE_POLICY` (D-005): SAIMAIL has no receiver-owned
semantic model of what the human already knows, so no novelty score, no
sender-declared novelty and no model claim that "the human probably never
noticed this" is implemented or implied.

## Approved advice stays private and receiver-owned

The generated adapter accepts only `SemanticallyReviewedAllyAdvice`, reuses
`HumanPrivateLetter` with `SUBJECT = ALLY_ADVICE` and the exact canonical
ALLY1 body, and adds no review report, corpus identity, reviewer metadata or
model identity to the letter or to clear HENV1 routing fields. The existing
manual B-012 path remains valid and unchanged.

Approval never seals HENV1, writes `HumanPrivateStore`, admits or reserves
attention, prioritizes, notifies or delivers. Sealing, storing and receiver
admission remain explicit later calls, and B-011 remains sovereign over
attention: a candidate that passed every semantic dimension may still never be
shown. The generation layer carries no allocation or deferral authority, and
reviewer rationale is never automatically fed back into the generator.

## Honest semantic limit

The gate does not mechanically prove that the pattern is real, that an
observation is objectively true, that evidence semantically entails the prose,
that counterevidence is globally strongest, that motive inference or flattery
was perfectly detected, that the advice is novel or useful, or that one
reviewer — or two agreeing models — is correct. It provides explicit source
bounds, full-corpus review visibility, semantic separation, an independent
review invocation, fail-closed uncertainty, no automatic rewrite loop and
provenance of what was reviewed. That is the actual guarantee.
